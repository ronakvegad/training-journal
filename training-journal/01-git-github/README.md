## 💡 Key Takeaways

- Every project should start with `git init` and a meaningful `README.md`.
- Commit early, commit often — each commit should represent **one logical change**.
- Use **branches** for every feature or fix; never commit directly to `main`.
- GitHub is not just a backup — it's a **collaboration and discovery** platform.
- Open-source contributions start with a **fork** and a clean Pull Request.
